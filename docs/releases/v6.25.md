# V6.25 — trees rebuilt as actual trees, they fall, and one editable tilesheet

V6.24 was rejected: the trees "still look like shit" and "dont look realistic".
V6.24's rounded geometric domes were replaced, not tuned.

## Trees: branch skeletons, not domes

`TerraTrees.grow()` builds a **6-connected log skeleton** — a trunk that may lean,
primary branches that reach outward on a golden-angle spiral, and twigs — and then
hangs separate irregular **leaf bunches** on the twigs. That produces visible trunks,
real branch gaps, lumpy asymmetric crowns and species-specific architecture:

* oak: broad decurrent crown with several branch tiers
* birch: slender pale bole, small high crown, a three-stem clump variant
* spruce: whorled horizontal branches that shorten upward into a cone
* jungle: tall clean bole, umbrella crown, emergent tower variant
* acacia: bent trunk with a flat, wide umbrella
* dark oak: short thick trunk, dense crooked branches
* swamp: drooping branches with hanging leaf strands
* bush: several small bunches near the ground

All 34 silhouettes, all three size tiers (Normal / Large / Giant) and the Tree Size
slider are kept. The LOD silhouettes are measured from the real geometry, so they
automatically changed with it. Headless worst case: 1103 leaves of the 1200 budget,
268 logs, 14-block half-span — no truncation, and cheaper than V6.24's solid domes.

`docs/screenshots/v6.25-trees.png` is a headless isometric render of the real voxel
geometry for all 34 silhouettes, and `v6.25-trees-and-lod.png` compares real trees
with the distant LOD silhouettes. Neither is a GPU screenshot.

## `/treefall` actually works on the new trees

The existing falling-tree planner only understood a straight trunk with a small
canopy. Four concrete bugs were found and fixed:

1. **Leaning trunks were disconnected.** A lean jumped one block diagonally, so
   everything above the first bend was not 6-connected to the stump. The planner
   saw only 3 logs and no reachable leaves, so most species refused to fall.
   Bends now leave an elbow log on the same layer.
2. **A conifer whorl above the trunk top floated** and stayed standing after the
   fall. Branches now anchor their origin cell and whorls stop at the trunk top;
   a top twig connects the crown and the candle spire.
3. **2×2 trunk bases pinned the tree upright** ("held up by something else"). A
   genuine 2×2 base (three or four logs on one layer, two on the cut layer) is
   now part of the falling tree. A single log resting on a stone still blocks the
   fall, so player-built structures remain safe.
4. **Limits were far too small** for branch networks: `MAX_LOGS 160 → 480`,
   `MAX_LEAVES 700 → 1400`, `LEAF_REACH 4 → 6`, `MAX_SPAN 14 → 18`.

`test/bc/Tests625.java` builds a real V6.25 tree of every species at Normal and
Giant size into a flat world, chops the base log, and asserts it topples and lands
with no trunk left standing. `TestsFall` still passes including its "log on a
stone does not fall" case.

## One tilesheet with ALL textures

`tilesheet.png` (shipped next to `Blockcraft.exe`, master copy in
`textures/Blockcraft-tilesheet.png`) is a **single 1024×1024 RGBA PNG** containing
all 1024 native 32×32 tiles. Cell `(row, col)` is atlas tile `row*32 + col`.

* Edit it in any pixel editor, keep 1024×1024 and alpha, save as PNG.
* In game: `/tilesheet` or **Options > Resource Packs > Tilesheet**.
  Changes appear immediately at full 32×32 resolution — no Java, Python or
  compiling, no restart.
* `/tilesheet export` regenerates the master + indexes. `/tilesheet` reports how
  many tiles are active.
* Indexes: `textures/TILESHEET.tsv`, `textures/tilesheet-index.html` (searchable
  picture index), `textures/tilesheet-map.png` (2× numbered reference map),
  `package/TILESHEET.txt` (guide shipped with the Windows build).
* Developer import: `python3 tools/tilesheet.py import <edited.png>`, then rebuild.
* Only cells that **differ** from built-in art are applied, so an untouched sheet
  is a complete no-op. Animated tiles (water, lava, portal, fire, ...) are skipped
  so animations keep running; edit those via `resourcepacks/MyTextures/animations/`.
* `Tilesheet.apply()` overlays the final 32px render atlas; `applyLow()` keeps the
  CPU 16px atlas (LOD colours, held item icons) in sync.

`tools/verify_release.py` now also checks `bc/Tilesheet.class` and `bc/Trees.class`
in the packaged jar/exe.

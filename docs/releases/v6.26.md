# V6.26 — no more LOD pops, and crash-hardened rendering

## LOD popping

Three concrete causes were found and fixed in `src/bc/Lod.java`:

1. **Instant appearance.** A tile was drawn the same frame its VBO finished
   uploading. With `lodMaxRequests = 4` and `lodMaxUploads = 8`, tiles arrived a
   few frames apart, so walking or turning produced hard "pops". `Tile.readyFrame`
   now starts an 18-frame smoothstep fade (`Lod.fadeIn`) implemented with
   `GL14.glBlendColor` + `glBlendFunc(GL_CONSTANT_ALPHA, GL_ONE_MINUS_CONSTANT_ALPHA)`.
   Constant alpha gives each tile its own opacity without touching vertex colours,
   so it works in both the GLSL LOD path and the fixed-function fallback. At
   `fade == 1` the output is byte-for-byte the old opaque rendering, and
   `glBlendFunc(770, 771)` / `glDisable(GL_BLEND)` are restored afterwards.
2. **Hard horizon cull.** `Lod.distanceFade` fades the outermost 10% of
   `fogFarBlocks` to zero, so CPU culling never removes a still-visible tile.
   Tiles closer than 90% of the horizon stay fully opaque — a short render
   distance no longer dims nearby terrain.
3. **Split thrash.** `splitDistance()` was re-evaluated every frame, so a tile
   exactly on the boundary flipped between its own mesh and its four children
   continuously. Each tile now remembers `lastSplit` / `splitFrame` and uses a 6%
   hysteresis band (1.06× when already split, 0.94× when not).

## Random crashes

No single reproducible stack trace was available, so the failure modes that can
actually escape to the render thread were closed and everything else was made
diagnosable:

| Fix | Failure it prevents |
| --- | --- |
| `build()` sizes the upload buffer from `bb.limit()` and derives `vcount = bytes/16` | `BufferOverflowException` when a builder wrote more bytes than it counted |
| `request()` catches a rejected `pool.execute` | leaked `inflight` slot permanently freezing all LOD requests |
| `retired` flag on evicted / replaced tiles; `uploadPending` and the draw loop skip it | use-after-free of a deleted VBO, double delete, ghost tiles |
| `uploadPending()` wraps `glBufferData` in try/catch | a driver/GL error killing the frame |
| per-tile try/catch in the draw loop, plus `vbo != 0` / `count > 0` guards | one bad tile aborting the whole render |
| `Renderer` wraps `lod.render(...)` and calls `invalidateAll()` on failure | any LOD exception taking down the game |
| mob snapshot taken **before** `glBegin` in `renderEntityShadowCasters` | `ConcurrentModificationException` from net/mod threads and GL left inside begin/end |
| `coveredBox()` null guards for `rend` / `g` | NPE in headless / early-startup paths |
| `Main.installCrashLogger()` → default uncaught-exception handler | every remaining crash is written to `crash.log` with thread name + stack trace |

`test/bc/Tests626.java` runs a four-thread, 24-tile headless LOD build stress test
(no exceptions, no `vcount`/byte mismatches), checks the fade and hysteresis
functions, and asserts every guard exists.

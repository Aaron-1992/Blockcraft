# V6.18 — panoramas, Advanced Video and frame-spike work

This update addresses five requests together: better redstone, the new biomes not
showing on Create New World, a new panorama, **all** video settings configurable
in game behind a debug option, and the large frame spikes / retained memory.

## New biomes visible on Create New World

`WorldPreview.COL` assigned colours for biome ids 0–27 while `Biomes.N` is 33.
Ids 28–32 (Cold Ocean, Lukewarm Ocean, Deep Cold Ocean, Deep Lukewarm Ocean,
Deep Frozen Ocean) therefore rendered as black squares. They now have colours,
and `WorldPreview.color(int)` falls back to a visible green for any biome added
in the future instead of returning zero.

The screen also gained:

* a colour key (up to eight swatches of the most common biomes) drawn inside the
  preview map;
* a content line: `N of 33 biomes in view - new oceans, reefs & kelp - villages,
  temples & ruins - bonus chest`;
* a hover hint naming the biomes actually present;
* a **New Oceans** switch bound to `WorldSettings.aquatic` (shown on
  windows 300 px and taller);
* a preview cache key that includes `aquatic`, `structures`, `bonusChest`,
  `mapId` and `structVer`, so changing a feature really redraws the map.

## New panoramas

`Panorama` now has three presets and a Cycle mode, selectable under
**Options → Video → Panorama** and in the Advanced tab:

| Preset | Seed | World | Character |
|---|---|---|---|
| Classic | 6120 | Default | the original view, unchanged scoring, speed and sky |
| Coral Coast | 20261018 | Default, aquatic | slower turn, warmer sky, scoring biased towards warm/shallow oceans |
| Snowy Peaks | 90210 | Amplified | faster turn, sunrise sky, scoring biased towards high snowy relief |
| Cycle | — | — | a different preset each time you return to the title or click the button |

`Panorama.pick(Gen)` and `candidates(Gen)` keep their exact old behaviour for
Classic (the existing tests and `PanoView` still use them). Vista results are
cached per preset, so switching back does not rescan the terrain.
`Panorama.switchTo(Game)` only restarts a panorama that is actually running;
changing the setting inside a world simply applies on the next title screen.

## Debug option → all video settings in game

Turning on **Debug Video** in Options → Video reveals a fifth **Advanced** tab.
It exposes the standard settings with wider ranges *and* the values that used to
be hardcoded:

* Display: render distance 2–32, FOV 10–150, LOD 0–1024, brightness, GUI scale
  Auto/1–8, VSync, fullscreen, Fast GPU, render scale 25–100%, max FPS 0–1000,
  shaders, smooth lighting, water quality, colour look, clouds, leaves, weather,
  effects, bushy leaves, animated mipmaps, panorama, the debug switch itself.
* Shaders & effects: shadow map 512/1024/2048, cloud resolution Full/Half/Quarter,
  cloud raymarch steps 16/32/48/64, bloom Off/Low/Full, shadow refresh interval,
  maximum shadow age, particle cap 0–2000.
* Performance & memory: chunk generation threads, mesh workers, chunk cache
  32–2048 MB, chunks unloaded per frame, timed autosave interval, async chunk
  saves, plus a Reset button, Apply & Save and live diagnostics.

All new fields live in `Options` and are read/written by `load()`/`save()`, so
they persist in `options.txt`. `Game.applyVideoTuning()` pushes them into the
live renderer once per tick and whenever the options screen is open; it is
idempotent and never touches OpenGL without an initialised shader pack.

## Redstone

* `RedstoneLogic.unloaded(World, Chunk)` is called on chunk unload and removes
  queued events, pending deadlines, sensors, comparators, torch burnout records,
  button/note/plate state and extension timestamps for that chunk. Previously
  these survived forever and could fire as ghosts when a chunk was loaded again.
* The periodic sensor and comparator scans reuse one scratch list instead of
  copying both sets every other tick, and drop entries whose chunk is gone.
* The event budget is now 4096 per tick (was 65536). Remaining due events are
  handled on the next tick, so one huge circuit cannot produce one huge frame.
* `Redstone319` network solving now uses `Packed` primitive long sets/maps and
  int/coordinate queues reused per thread instead of `HashMap<Long, Integer>`,
  `HashSet<Long>` and `ArrayDeque<Integer>`/`int[]` per wire. Behaviour is
  unchanged; the per-change allocation disappears.
* Pending repeater/observer/torch deadlines and torch burnout are now stored in
  `level.properties` as remaining ticks and restored on world load, so a machine
  no longer resets itself when you quit and come back.
* F3 shows the power, input, repeater delay, comparator mode, burnout time and
  queued event count of the redstone block you are looking at.

## Frame spikes and retained memory

Measured before the change (headless `ThreadMXBean` probes): `Mobs.tick`
allocated ~85–330 KB per call, `Game.tick` ~64–96 KB, and `Phys.move` created a
`double[384]` on every player/mob/item movement (growing it with `Arrays.copyOf`).

After the change, in the same `GameTests.newGame(0)` fixture: `Phys.move` is
0.15 KB/call (was ~3 KB for the buffer alone), `Mobs.tick` with 30 cows is
0.52 KB/call (was ~328 KB/call), `Game.tick` with 30 cows is 5.5 KB/call (was
~96 KB/call), and `World.tick` stays at 0.21 KB/call. These are allocation
numbers, not frame times: GPU-hardware timings still need a real machine.

* `Phys` reuses a per-thread collision buffer; `scratchCapacity()` is a test hook.
* `World.tick` reuses one tile-entity snapshot instead of copying
  `new ArrayList<TileEntity>(tiles.values())` every tick.
* `World.saveChunk` takes a block snapshot and writes GZIP files on a
  low-priority `chunk-save` thread (switch: Async Chunk Saves). `shutdown()`
  waits for queued writes. LOD summaries stay on the main thread so `lod.dat`
  remains consistent.
* `World.saveAll` is now a bounded walk (`saveStep`), and a timed autosave
  (default every 1200 ticks) spreads six chunks per frame instead of writing the
  whole world in one frame on quit or dimension change.
* Chunk unloads are budgeted (`unloadBudget`, default 2) and a configurable
  `chunkCacheMb` ceiling gently widens the unload radius when too many chunks
  are resident.
* `Game.addParticle` enforces a hard `particleBudget` cap (default 500) for all
  particle sources; `Fire.particles` uses the same cap.
* Shadow and cloud settings are now real tunables: a smaller depth FBO, fewer
  cloud raymarch steps, lower cloud/ray target resolution, cheaper bloom and a
  longer shadow refresh interval all reduce GPU work and VRAM instead of merely
  lowering a default.
* `World.genThreads(Options)` / `Renderer.meshWorkerCount()` make the worker
  counts configurable; `Tex.setAnimatedMips` can skip the mipmap rebuild during
  atlas animation.

## Verification

Run `python3 tools/build.py`, `python3 tools/runtests.py unit`,
`python3 tools/runtests.py equivalence`, `python3 tools/glsl_check.py` and
`python3 tools/verify_release.py` after `--patch`. GPU-hardware performance and
the visual screenshot workflow still need a machine with a real GPU / Xvfb.

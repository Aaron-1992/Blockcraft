# V6.19 — moonlight, entity shadows, LOD control and bigger caves

## Moon shadows

`Shaders.setLight(sunAngle, enabled, options)` now picks the light that throws
shadows. During the day it is the sun; once the sun is below the horizon the
moon — the exact opposite direction — takes over the same depth-only shadow
map. `sunDir` in every shader is therefore the *active* light, while
`realSunY` keeps the true time of day for fog glow and cloud colour.

* `moonF` blends the warm sun tint to a cool blue; `moonUp` is the dim
  moonlight strength (`Options.moonBrightness`, default 0.45).
* Terrain, water, LOD, entity and cloud shaders all follow the moon, so the
  night picture stays consistent. Clouds are dimmed and tinted blue instead of
  being bright white at midnight.
* `Renderer` rebuilds the shadow map when the light direction flips at dusk,
  and the shadow map is refreshed by the existing interval/max-age logic.
* **Moon Shadows** and **Moon Light** are independent Advanced-tab settings.

## Entity shadows

`Renderer.renderEntityShadowCasters()` draws a five-quad crossed box
silhouette for up to 96 mobs within 48 m into the same depth-only shadow map.
`DEPTH_FS` gained a `solid` uniform so those quads bypass the atlas alpha test;
no new textures, programs or framebuffers are created. Sizes are per mob type
(`entityShadowWidth` / `entityShadowHeight`: chickens small, spiders wide and
low, iron golems tall). **Entity Shadows** toggles it. Because the map is
shared, mob shadows follow both the sun and the moon automatically.

## The player's hand is shader-lit

`ENTITY_FS` previously returned a flat `handLight` colour for the viewmodel,
bypassing all world lighting. The `handPass` branch now optionally
(`handShader`) computes a face normal from `vRel` derivatives and applies:

* sun and moon directional shading with the day/night tint,
* the sunrise fog glow,
* all twelve dynamic lights with real distance falloff,
* then the single gamma-correct lightmap sample as the base.

`Shaders.useHand` passes the *plain* lightmap sample when the shader path is on
(the nearby-light max would double-count the dynamic lights) and keeps the old
`HandLighting.withNearby` flat path when **Hand Lighting** is off.

## LOD performance and falloff

Distant terrain was the remaining source of frame spikes. It issued one draw
call per tile, uploaded up to 64 vertex buffers per frame and allocated a root
tile list, an `int[2]` per root, two comparators and a colour array every frame.

* `lodFogStart` / `lodFogEnd` / `lodFalloff` — fraction of the LOD horizon
  where distant terrain starts and stops fading into fog. `LOD_FS` applies the
  fade; the CPU culls every tile beyond `lodFogEnd * horizon` entirely.
* `lodDetail` — quadtree split-distance bias (Coarse / Normal / Fine).
* `lodMaxRequests` (4), `lodMaxUploads` (8), `lodMaxDraws` (0 = off) and
  `lodWorkers` (0 = auto) bound the work done in a single frame.
* `Lod.render` reuses its root-tile `ArrayList` and `int[2]` objects, two
  cached comparators, and a cached `float[4]` texture-env colour. No per-frame
  garbage from the LOD walk.
* `Lod.detailFactor` and `Lod.fogFarBlocks` are pure helpers with unit tests.

## Better caves and world generation

`WorldSettings` gained `terrainVer` (1 = V6.18 terrain, 2 = V6.19) and four
multipliers: `caveScale`, `caveDensity`, `mountainScale`, `ravineScale`. They
are saved in `level.properties`, so **existing saves keep their exact old
terrain**. New worlds copy the Advanced-tab values via
`Screens.applyNewWorldSettings` when you press Create New World.

For `terrainVer >= 2`, `TerraGen`:

* carves three overlapping systems — stretched worm tunnels, a second larger
  network that joins them, and deep cheese caverns — using the *existing*
  noise fields at different scales/offsets (no new seeds, no change to old
  worlds);
* opens more cave mouths (`entranceBig`);
* widens mountain regions, multiplies peak height by `mountainScale` and adds
  sharper ridges on top;
* widens ravines and lowers their required strength by `ravineScale`.

`WorldPreview`'s cache key includes the new settings, so the Create New World
map redraws when a terrain slider changes.

## Settings

All new values live in `Options`, are clamped on load, written to
`options.txt` on save, and are visible in **Options → Video → Debug Video →
Advanced** (44 rows now: display, shaders & effects, light & shadows,
performance & memory, LOD / distant terrain, world generation, live
diagnostics). `Reset Advanced` restores them. F3 shows the live LOD tile
count and the moon-shadow state.

| Setting | Default | Range |
|---|---|---|
| Moon Shadows / Entity Shadows / Hand Lighting | on | on/off |
| Moon Light | 45% | 15–100% |
| LOD Falloff | 1.00 | 0.40–2.00 |
| LOD Fog Start / End | 35% / 100% | 0–95% / start+5–100% |
| LOD Detail | Normal | Coarse / Normal / Fine |
| LOD Builds / Uploads / Draw Cap / Workers | 4 / 8 / off / auto | 1–32 / 1–64 / 0–4096 / 0–4 |
| V6.19 Terrain | on | on/off (new worlds only) |
| Cave Size / Density / Mountain Scale / Ravine Scale | 1.6x / 1.3x / 1.5x / 1.3x | sliders |

## Verification

* Headless unit suite: **7,713,256 assertions passed, 0 failed** (seven new
  V6.19 regression groups, plus the updated hand-lighting shader assertion).
* Strict equivalence: terrain / world / tick fingerprints are still identical
  to the original Update 3.5 jar; 397 fingerprints identical.
* `tools/glsl_check.py`: all 21 shaders parse, including the modified world,
  water, entity, LOD and depth programs.
* `tools/verify_release.py`: both packaged executables report version 6.19.

GPU frame times, real-driver shader compilation and the screenshot workflow
still need a machine with a real GPU/Xvfb; no measured FPS gain is claimed.

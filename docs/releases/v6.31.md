# V6.31 — LOD cross-fades, montage trailer, borderless fullscreen, clean menus, new caves & structures

The user reported: *"Lod popping still exists and the trailer is weird its just one camera thingie that goes through the wordl make it like the normal minecraft trailer also clean up the files and the menus and add borderless fulscreen also cave entrances always look the same just do it like minecraft does just let the caves go through the ground and caves still need a completely new rework and the structures too"*.

All six items are addressed. No Mojang code or assets are introduced.

## 1. LOD popping — fixed at the root

V6.26 faded **newly uploaded** tiles, but `Lod.refresh()` still replaced a
rebuilt tile in one frame and `visit()` still switched between a parent and
its four children in one frame. Those one-frame swaps were the pops.

* `Lod.Cross` keeps the **old mesh fully opaque** while the replacement blends
  in over `FADE_FRAMES`; the old VBO is only deleted when the fade completes.
  Eviction skips tiles taking part in an active cross-fade.
* `drawNode()` keeps a **coarse fallback visible for the whole fade-in**
  instead of dropping it the instant the new mesh arrives.
* `splitWeight()` replaces the hard 0.94/1.06 hysteresis switch with a
  **continuous 28% distance band** (0.86×–1.14× `splitDistance`). In the band
  both the parent and its children are drawn (children with blended opacity),
  so walking across a LOD boundary never swaps two meshes instantly.
* `childrenReady()` / `requestChildren()`: a split only starts exposing
  children once all four have a mesh, removing "children pop in one by one".

## 2. Trailer — a montage, not one flythrough

`Trailer.java` was rewritten. It is still exactly 60 seconds and still runs
inside the game with the real renderer, but now:

* **24 hard cuts** (2.0–5.5 s each) instead of 8 long shots;
* **eight camera moves** — Glide, Dolly, Orbit, Crane, Dive, Static pan,
  Top-down, Chase — with genuinely different maths;
* **eight scattered locations** from a fixed seed, so the camera does not
  stay in one place;
* a **cut-up** dawn / noon / storm / sunset / night arc rather than one
  continuous time-lapse;
* big **word cards** ("A WORLD", "EXPLORE", "BUILD", "DIG DEEPER", "SURVIVE",
  "TOGETHER", "BLOCKCRAFT") between bursts of fast cuts, 0.14 s black flashes
  on every cut, and the block-built logo finale;
* four-act soundtrack and foley stings from the real CC0 WAVs.

`Watch Trailer (1:00)` on the title screen, `/trailer` in game, any key or
click skips, and the exact screen/camera/weather/options are restored.
`java -jar blockcraft.jar --trailer-plan` prints the deterministic plan;
see `docs/releases/v6.31-trailer-plan.txt` and
`docs/screenshots/v6.31-trailer.png` (headless storyboard, not a GPU shot).

## 3. Borderless fullscreen

`Options.borderless` is saved in `options.txt`. `Game.setBorderless()` creates
an undecorated window exactly the size of the primary monitor
(`GLFW_DECORATED = FALSE`, windowed monitor `NULL`), so Alt-Tab and overlays
keep working. `applyDisplayMode()` applies the saved fullscreen **or**
borderless setting at startup. Toggles: **Options > Video > Borderless**, the
Advanced tab, and `/borderless`. F11 still does exclusive fullscreen.

## 4. Cleaned-up files and menus

* `releases/` went from **1.3 GB to 156 MB**: 25 obsolete update packs and
  three loose full-Windows-zip copies were deleted; only the current pack,
  the three most recent and `6.16` (used by `perf.yml`) remain. Canonical
  downloads live on the GitHub Releases page.
* New `docs/FILE-LAYOUT.md` documents the source tree and the extracted game
  folder.
* The title screen is now **five clear buttons** (Singleplayer, Multiplayer,
  Watch Trailer, Options, Quit). Mini Games, Skins, Resource Packs, Mods,
  All Blocks Gallery and Credits moved to a tidy **More...** screen
  (`Game.S.MORE`, Esc to go back). The Video settings were regrouped and the
  layout test still passes at all seven window sizes.

## 5. Caves — completely new, with naturally varied entrances

`caveVer = 5` for **new worlds only** (old saves keep their version). New
`Caves5.java`:

* two overlapping large-scale 3D cheese fields (y=8..96), two spaghetti
  scales, thin noodle tubes, hashed giant halls, local aquifers and lava;
* caves **thin out towards daylight**, so the surface is not swiss cheese;
* **no built cave mouths at all**. The carver is allowed to run up to the
  terrain surface on dry land, where two smooth 2D noise fields decide where
  it breaks through. The opening is that noise outline — craters, ragged
  slits, wide throats, narrow necks — and a funnel that widens downward runs
  22 blocks into the ordinary cave network. No two entrances look the same;
* `Caves5.landBiome()` keeps oceans, rivers and beaches sealed;
* `mouthSurface()` for trees/spawn now asks the carver itself whether a cave
  reached daylight.

Headless 96×96 land sample at seed 20261107: 930 open surface columns in
**6 separate openings** with sizes `1, 6, 25, 79, 387, 432` — all 930 lead at
least 10 blocks down into carved cave. `docs/screenshots/v6.31-caves.png`
shows the cross-section and the top-down outlines (not a GPU screenshot).

## 6. Underground structures — completely new

New `CaveStructures5.java`: eight types (Mineshaft, Geode Cathedral, Ancient
Hall, Lava Foundry, Mushroom Grotto, Flooded Cistern, Crystal Vault, Dungeon)
on a 96-block hashed grid. Each is a rotunda with two side chambers, four
arched corridors, a solid floor, pillars, supports, lights, a type-specific
centrepiece, loot/spawners, and a **straight tunnel out to a real carved cave**
(`linkToCave`), so it is never sealed. All stamping is in world coordinates,
so chunk seams agree. `CaveWorks.finish()` uses this set for `caveVer >= 5`
and leaves the old six room types for older saves.

# V6.20 — minimap, big world map and the fixed title panorama

## Two maps

`src/bc/MapView.java` is new. It draws two ordinary `Gui.Image` pictures, so
exactly the same code runs in the OpenGL GUI and in the headless
`GuiRaster` used by the screenshot tests.

* **Minimap** — a 64 / 96 / 128 GUI-unit square in the top-right of the HUD,
  drawn from `Game.drawHud()` while playing (or chatting). Loaded chunks
  supply their real `Chunk.hm`, `Chunk.biome` and top block; the world
  generator fills everything beyond the loaded area. It has relief shading,
  biome colours (the same palette as Create New World), water/snow/sand/stone
  overrides, a rotating or north-up orientation, a player arrow, red/green
  mob dots, a north marker and X/Z coordinates.
* **Big map** — press **M** (or the Done/Close button) for a 256×256 picture
  covering 512 to 16,384 blocks. Pan with WASD / arrows or click the picture,
  zoom with the wheel or `+`/`-` (six steps: 2, 4, 8, 16, 32, 64 blocks per
  pixel), `R` recentres on the player, `G` toggles the grid, `B` toggles mob
  dots. It shows the centre coordinates, a coordinate grid, terrain, mob dots
  and the player arrow. The screen pauses the world like a menu and releases
  the mouse.

The big map is filled **1,024 pixels per frame** (256 after the first full
pass), not in one burst, so opening it cannot create a frame spike. Both maps
share `MapView.colorAt(World, Gen, x, z)`; unloaded columns come from
`Gen.column`, loaded columns from live chunk data, so player edits show up.
`MapView.update(Game)` is called once per frame from `Game.update` and does
nothing when both maps are hidden.

| Control | Action |
|---|---|
| `M` | open / close the big map |
| WASD / arrow keys | pan 32 zoom-scaled blocks |
| wheel / `+` / `-` | zoom one step |
| click on the picture | centre the map there |
| `R` | centre on the player |
| `G` / `B` | grid / mob dots |
| `Esc` | close |

## Settings

Nine new `Options` fields are clamped on load, written to `options.txt` and
exposed in game:

| Setting | Default | Range |
|---|---|---|
| Minimap | on | on/off (also on the Game tab) |
| Rotate Minimap | off | on/off |
| Mob Dots | on | on/off |
| Minimap Size | Normal | Small / Normal / Large (64/96/128) |
| Minimap Radius | 128 m | 32–512 m |
| Map Refresh | 3 frames | 1–20 (a rotating map redraws every frame) |
| Big Map Zoom | 8 m/px | 2–64 m/px |
| Map Grid | on | on/off |

`Screens.ADV_ROWS` is now **50**: a "MAPS & MINIMAP" section was added to the
Debug Video → Advanced tab, and `Reset Advanced` restores the map defaults.
`Options → Game` has a quick Minimap switch plus a Big Map hint, and the
controls list documents `M`.

## The panorama was not rendering

The title background is a real turning world (`Panorama`). Its fade-in waited
for

```java
world.loadedAround(cx, cz, 3) >= 36 && meshed(cx, cz, 2)
```

and `meshed` required **every one of the 16 sections in all 25 chunks** to
have `dirty == false && inFlight == false`. Since Update 3.11 the renderer
uses demand meshing: `Renderer.meshCandidate` deliberately defers sealed cave
and interior sections that the current view cannot reach. Those sections stay
`dirty` forever, so `shown` never rose, `fade()` stayed at `1.0`, and
`Ui.backdrop` painted a solid black rectangle over the whole menu. The world
was being drawn behind it; the player simply never saw it.

Fixes:

* `Panorama.meshed` now uses `Renderer.meshLoadingReady(world, chunk)`, the
  same view-aware readiness rule the world-entry loading screen uses, and
  falls back to the raw section check only in headless tools with no renderer.
* `Panorama.readyToFade(loaded, meshed, elapsed)` adds a **six-second**
  timeout once chunks are lit. A slow generator or a hidden section can no
  longer keep the fade at zero forever.
* `Ui.backdrop` no longer paints a fully opaque black overlay. It draws a
  **generated 2D landscape** (`Panorama.drawFlat`) immediately — sky, sun,
  three ridge layers sampled from the preset's generator — and cross-fades it
  out as the 3D world fades in. If the 3D world cannot be installed at all,
  the 2D landscape stays on screen instead of a black title.
* `Panorama.start` catches a failed vista search and installs an emergency
  vista; `install()` is wrapped so a thrown exception cannot break the frame
  loop. `Panorama.stop` releases the LOD renderer, and `switchTo` no longer
  skips a preset when Cycle is active.

The 2D fallback is cached as plain RGB per preset; only its alpha is
rewritten (quantised to 32 levels) while fading, so there are at most 32
small texture uploads during a fade.

## Verification

* Headless unit suite: **7,713,324 assertions passed, 0 failed** (eight new
  V6.20 regression groups for option persistence, the Advanced rows, map
  colours, the minimap, the big map, M/wheel keys, panorama readiness and the
  title fallback).
* Strict equivalence: terrain / world / tick fingerprints are still identical
  to the original Update 3.5 jar; **397 fingerprints identical**, 64 changed
  on purpose, 150 new.
* `tools/glsl_check.py`: all **21** shaders parse (no shader source changed).
* `python3 tools/build.py` → `[build] OK (Update 6.20)`, 163 sources,
  `build/blockcraft.jar` 7.28 MB / 1,222 entries, `build/Blockcraft.exe`
  7.35 MB.
* `tools/verify_release.py` (via `tools/make_release.py 6.20`): both packaged
  executables report `version=6.20`, 32px atlas, pixel-sprite bow;
  `source.sha256=672346bb2ae84b9c42e6a4b7cee18c8cea30c1dd2568bdd0c837702842bcf31a`.
  `build.py` and `verify_release.py` now also record/check the hashes of
  `Options`, `Screens`, `Ui`, `Panorama` and `MapView`, so a stale map build
  cannot be published.
* GitHub Release workflow `41386374618` and both CI runs (`41386362682`,
  `41386374641`) succeeded for the first V6.20 build. The final V6.20 build
  below was republished after polishing the big-map layout and the fallback
  skyline (see `docs/screenshots/v6.20-*.png`); its hashes were recomposed
  from the committed patch pack.

Real-GPU / Xvfb shader compilation, screenshot diffs, measured frame-time
gains and a Windows playtest remain unverified; no FPS claim is made. The new
maps are ordinary 2D GUI work and do not alter terrain generation, world
saves or the legacy world/tick behaviour.

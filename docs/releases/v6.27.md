# V6.27 — resource-pack texture editing works again

## The bug

The user reported: *"I used the old version of editing textures but it does not
work, the resource pack uses the normal textures even if I changed the file
inside of the pack."*

Reproduced headlessly (`test/bc/Tests627.java`): build a temporary
`resourcepacks/MyTextures` pack with `pack.properties` (`tileSize=32`) and a
magenta `tiles/0003_stone.png`, select it, build the 32px render atlas:

```
BEFORE tilesheet: tile3(5,5) = FFFF00FF   (the pack edit)
AFTER  tilesheet: tile3(5,5) = FF878984   (default stone)
```

V6.25's `Tilesheet.apply()` compared each sheet cell against the **current
render atlas**. With a resource pack active, the atlas contains the user's
edited art while `tilesheet.png` contains the default art, so every pack edit
was seen as "different" and overwritten by the default. `Tilesheet.applyLow()`
had the same flaw for the CPU 16px atlas (LOD colours, held item icons).

## The fix

* `Tilesheet.export()` now also writes a **pristine reference**
  `Blockcraft-tilesheet-default.png`; `tools/tilesheet.py export` ships it as
  `package/tilesheet-default.png` next to `tilesheet.png`. `import` deliberately
  never overwrites the reference.
* `Tilesheet.apply()` / `applyLow()` / `changedTiles()` compare the editable
  sheet against that reference via `editedCell()`. Only genuinely edited cells
  are applied; everything else is left exactly as the active resource pack
  produced it. Without the reference the overlay is a safe no-op.
* An edited tilesheet cell still wins over a resource pack (explicit user edit
  takes precedence) — covered by a second regression test.
* `ResourcePacks.applyPostProcess()` now applies PNG tile overrides for
  **every** pack kind, including the built-in Vibrant / Retro colour grades and
  classic-base packs, through one shared `applyTileOverrides()` path.
* Diagnostics: **Reload PNGs** reports `ResourcePacks.overrideCount()` and
  `/tilesheet` reports edited cells + pack overrides + active pack id, so a
  mis-selected pack is immediately visible.

Priority is now: default art → resource pack → only the cells you actually
edited in `tilesheet.png`.

## Verification

`runtests.py unit` (5 new `6.27:` groups including the exact reproduction and
its inverse), `equivalence`, 21 GLSL programs, `build.py`, `--patch`,
`make_release.py 6.27`, `verify_release.py` (now also checks
`bc/ResourcePacks.class`). No real-GPU/Windows playtest is claimed.

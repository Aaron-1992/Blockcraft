# V6.35 — deep worlds, depth-scaled caves, and every menu rebuilt

The user asked: *"i guess thats somewhat better make worlds so deep that you can get completely
lost and make caves crazier the deeper you go and redo ALL the menus from scratch ok? i iike the
preview of the world map when creating worlds though (THAT DOES NOT MEAN TO KEEP THAT WHOLE MENU)"*.

Three separate jobs, all done. No Mojang code or assets.

## 1. A 384-block-deep world

`Chunk.H` went from 256 to **384** (24 sixteen-block sections, 98,304 blocks per chunk). New
worlds are lifted by `WorldSettings.depth = 128`: sea level becomes **191** instead of 63, so
there are ~190 blocks of underground below it instead of ~62. Mountains reach above y=330, so the
new upper half is genuinely used. A wide headless sample found heights **146..333**.

Because the world is taller, the whole engine was extended carefully:

| Change | Why |
| --- | --- |
| `Chunk.SIZE = 256 * 384`, `SECTIONS = 24` | block/light arrays and meshing sections |
| `Chunk.writeBlocks` / `readBlocks` deep trailer (`BCDP`) | y=256..383 is appended after the classic 65,536-byte part. Old games see an unknown magic and stop; old saves still read byte-for-byte. A classic-sized scratch buffer still reads a deep file. |
| `World.packH` uses 9 bits for Y (25 bits each for X/Z) | the internal light/fluid/block queues can address y=383; bits 60..63 stay free for the removal-light tag. **`World.pack` itself is deliberately unchanged** because its keys are persisted in `raster.dat`, `circuit.dat` and distributed V6.10 sound-machine saves — all 4,003 native-save checks still pass. |
| `World`, `Renderer`, `Mesher`, `CaveCull`, `Lod`, `PerfBench`, `Game`, `Circuit` | height bounds and `sy < 16` loops now use `Chunk.H` / `Chunk.SECTIONS` |
| `Gen.SEA` is a per-world value set by `Dim.makeGen` | water, LOD water plane, map shading, panoramas, weather and portals all follow the lifted sea level |
| `TerraGen.Cl.genH` | climate, biome, snow lines and borders still use the *unshifted* generation height; only the final block height `o.h` is lifted |
| `WorldSettings.depth`, persisted as `worlddepth` | clamped to 0..128; old saves load with 0 |

Only **Create New World** with *Caves & Cliffs* on gets `depth = 128` and `caveVer = 8`; there is
a new **Deep World** switch in Settings > World and on the creation screen. Old saves keep their
own height and cave version — nothing in an existing world moves.

## 2. Caves get crazier the deeper you go (`caveVer = 8`)

`Caves8` keeps V6.34's rule — **one continuous 3D cave volume, no aperture, no funnel, no drilled
shaft** — and adds a single depth knob `crazy(y) = clamp((sea + 24 - y) / (sea + 24))`:

* **Daylight**: calm sheared spaghetti tunnels, a strong taper on cheese caverns, natural
  ragged mouths where the volume meets the terrain.
* **Middle**: worm radius grows with `1 + 1.8·d²`, cheese gates drop by `0.14·d`, water aquifers
  and the first big halls.
* **Deep** (d > 0.42): a low-frequency "mega cheese" field opens cathedral-sized chambers; giant
  halls get bigger and more common.
* **Abyss** (d > 0.60): a second, cross-sheared tunnel maze, lava seas below y=12, crystal /
  glowstone / amethyst clusters whose density scales with depth.

Measured on the headless cross-section `docs/screenshots/v6.35-caves.png`:

| Layer | Carved |
| --- | --- |
| Abyss, y 6–40 | **47.2%** |
| Deep, y 40–110 | **30.4%** |
| Middle, y 110–170 | **6.3%** |
| Daylight, y 170–surface | **4.0%** |

A 96×96 land sample has ~4.4% open surface columns and almost no lone vertical shafts. The
gradient is intentional: the further down you go, the harder it is to keep your bearings.

`CaveStructures8` has **twelve** types — the original six plus Crystal Cathedral, Fossil Hall,
Lava Forge, Lost Library, Abyssal Maze and Sunken Vault. All are returned by the *same*
`air(x,y,z,surfaceH)` that `Caves8.cause()` calls for every block, so a mega cavern can swallow
half a cathedral. Plans grow with depth (`r = 2 + 4·d`) and a second `slot=1` site only exists in
the abyss. Walls and floors are stamped only where the rock outside is solid, so a cave passing
through a wall stays open. The legacy sealed dungeon/mineshaft/stronghold generators remain off
for new worlds, and village sites still avoid cave mouths.

## 3. Every menu rebuilt from scratch — the Atlas UI

`Menus635.java` is a completely new menu system. `Game` now routes **all sixteen** menu states to
it; no `Screens.*` menu method is drawn any more (they remain as a regression/compatibility
surface). The design language is new: a dark numbered navigation rail, a cyan header rule,
large glass cards with coloured top strips, segmented three-column tabs, and a common footer
with the version and hint. Everything still goes through `Ui`, so clicks, keyboard focus,
scrolling, hints and toasts behave exactly as before.

Screens rebuilt: main menu, singleplayer hub, multiplayer hub, Create New World, Create
Multiplayer World, world list, multiplayer connection, mini games, settings, pause, more,
resource packs, mods, credits, loading and the waiting lobby.

**The live world-map preview is kept.** The user liked the map on Create New World, not the old
menu around it: the same `WorldPreview` widget is drawn in a new "02 / LIVE WORLD MAP" panel with
its colour key and biome count, and it now previews the actual `depth` of the world that will be
created. The Debug **Advanced** tab still calls `Screens.advancedTab`, so all 61 video/shader/
LOD/performance settings remain configurable in game behind Debug Video.

`test/bc/Scenes.java` gained 17 `atlas-*` scenes and `TestsUi` draws all of them at the seven
real window sizes — **399 screens, 3,645 widgets, zero layout problems**.
`docs/screenshots/v6.35-menus.png` is a headless software board of eight of them, not a GPU
screenshot.

# V6.15 — visible processing, dedicated component art and smooth rendering

## User-requested changes

- Eight original native 32px component surfaces replace borrowed block/plank textures on machinery. UV extents follow each component's actual dimensions, preserving uniform texel density rather than stretching an entire block texture across small parts. The same transformed geometry is used in world, held and Creative views.
- `KineticRender` draws machinery every render frame with partial-tick rotation, independent of chunk rebuilding. Kinetic ticks no longer dirty meshes for rotation; static world meshes do not draw duplicate machinery. Press ram, wheel/gears, gauges and moving belt treads use the per-frame path.
- `KineticTransport` implements straight horizontal powered segments, passive depots, visible persistent stacks, signed-speed travel, stopped belts, one hop maximum per tick, full-receiver waiting, dropped-item capture, endpoint ejection, hand insert/extract and cargo drops on break.
- Powered presses stamp whole visible batches on the belt/depot two blocks below. The batch is held under the ram while processing. Millstones accept dropped/hand-fed ingredients; empty-hand use collects output. Normal interactions never open the legacy machine screen. Old V6.14 internal press inputs are retained and can finish; visible processing waits until that legacy input is cleared.
- Routine motor/wrench/wheel status chat messages are removed. Aimed-at HUD information remains. Errors such as remote-client access restrictions still have feedback.
- Wheel torque is the axle projection of `r cross WaterPhysics.current`, summed at the rim. Still water produces zero, opposite falling/horizontal currents reverse rotation, and opposing torque cancels. The manual wheel reverse toggle is removed.

This is NOT full Create parity. Belt placement is segment-by-segment, straight/horizontal only; no connector tool, inclines, funnels, actor transport or full multiplayer. Wheel geometry/collisions remain native approximations. The [player guide](../../package/Create-foundation.txt) and [scope table](../create/STATUS.md) spell out the current limits. Existing material art was not replaced; only new cells 1005..1012 are added.

## Native checks and the issue they caught

Initial native checks caught an incorrectly seeded example waterfall: using source water plus a falling bit caused fluid updates to normalize it into still water. The wheel correctly stopped. The demo now uses true flowing-water cells below the source, and a dedicated regression repeatedly runs real fluid updates and verifies continued wheel torque. The first failed checks were not treated as a release pass.

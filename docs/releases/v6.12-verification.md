# V6.12: direct MIDI picker and GUI building

Right-click the MIDI Build Compiler in Creative to open an in-game local file browser. Home, Downloads, the optional MIDI folder, filesystem roots/drives, parent navigation and pagination are available. Selecting a `.mid` or `.midi` file previews a section, defaulting explicitly to the first five seconds. Spaces, Unicode names and case-insensitive MIDI extensions work without copying or renaming files. Start/Length, Preview, Build circuit, height selection, Close and Go to button are actual game widgets.

The screen captures its world and compiler position, not a transient crosshair. It reads a bounded file snapshot, holds the parsed physical plan, invalidates it when inputs change, and rechecks permissions, compiler presence, loaded chunks and all reserved cells before building. Default placement scans the whole footprint and raises above the highest occupied cell; it does not clear terrain or replace existing blocks. Legacy MIDI commands now report specific errors; `/midi` opens the picker and command `/midibuild` uses its saved anchor.

No playback machinery changed: ordinary repeaters, dust, note blocks and material-selected instruments remain independent of the compiler/file. Existing 1 MiB, type 0/1, 512-note, six-note-chord, 120-second selected duration and 256-block rail limits remain. Default five seconds is an explicit excerpt, not a full-song promise. Timing is 100ms with a fixed 100ms lead-in, with octave folding and no MIDI velocity/sustain/bend reproduction.

The reported `DSi_Shop_Midi_Perfect.mid` was not supplied. Its name was already valid; the generic command catch hid the true underlying error. This update fixes that diagnostic path and the command-heavy workflow, but does not claim that particular song was tested.
